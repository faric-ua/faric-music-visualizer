## v0.19.38 implementation

### Movable projectM settings
New:
- `app/src/main/java/com/saney/musicvisualizer/projectm/ProjectMSettingsPanel.kt`

Behavior:
- PulseDeck visual styling;
- non-dimming and non-modal;
- draggable from header;
- X/Y position persists;
- reset-position control;
- one composite panel with tabs:
  - AUTO
  - CENTER
  - EDGE FX
- tuning changes apply live while the panel stays open.

### AUTO semantics
- `AUTO OFF` is shown when manual mode is active.
- active state shows `AUTO 5s`, `AUTO 10s`, or `AUTO 15s`.
- tapping AUTO while manual enables automatic switching at the currently stored interval.
- tapping while AUTO is active cycles 5 -> 10 -> 15 -> 5.
- selecting 5/10/15 in the panel enables AUTO immediately.
- state persists in `ProjectMStateStore`.

Root cause of the previous “5 seconds but nothing changes” report:
- the screenshot showed `MANUAL`;
- changing the stored interval did not re-enable AUTO.

### Main-player composite editing
Main player:
- Layers -> Visualizer now gets a **⚙** button analogous to the GF gear.
- It opens the same movable projectM settings panel over the full composite player.
- Center/Edge changes are applied to `projectMMainView` live.
- this is specifically so the user can tune FG while seeing Shark + projectM + HUD together.

### Back lifecycle
Previous safe race fix used `releaseProjectMBlocking()` on the UI thread and caused a visible pause.

v0.19.38:
- `ProjectMView.releaseProjectMThen()` queues native release on the GL thread;
- activity remains lifecycle-safe;
- `finish()` happens from the release callback;
- both PulseDeck Back and Android system Back use the same path;
- no late destroy is allowed to kill the newly-created main renderer.
