## Власник

- Відповідати українською, коротко, простими словами. Дії на телефоні — **тільки пунктами меню** (`MUSIC VISUALIZER: 3 → 10 → 8`), без команд.
- **Формат відповіді — `docs/RESPONSE_ALGORITHM.md`** (з 2026-10-16, однаковий у всіх репо faric-ua; різні лише меню). Кожна робоча відповідь закінчується блоком **«Від тебе зараз:»**.

- Під час перевірки на телефоні — **один крок за раз**, перевірок — до 3.
- **Результати тестів — карткою з варіантами** (faric 20.10 00:36: «меню з пунктами й галочками, три значення: пас · не пас · не тестував, і кнопка відправити»): Claude дає картку-питання (до 4 пунктів за раз), у кожному «Пас / Не пас / Не тестував»; інше — своїм текстом.
- **M30s — запасний телефон**: тести на ньому лише коли faric скаже, що він вільний.
- **Як faric називає екрани (19.10):** **центр** — головна сторінка плеєра (PulseDeck); **ліво** — медіатека (бібліотека, свайп зліва направо); **право** — налаштування візуалізації projectM (свайп справа наліво: AUTO, ТОП / ВСІ, NEXT, BG / CENTER / EDGE FX, ⚙ FG, оцінки). Кнопка ⇧ унизу — Export Lab.
- Якщо faric каже «поки нічого не роби» — лише записати й чекати.

## Цикл роботи

1. Код + тести у своїй копії → гілка `feat/…` / `fix/…` / `docs/…` → PR у `main`.
2. CI: **Validate** — на кожен PR; **Android** — лише коли змінено `app/**`, `skin/**` або файли Gradle. Зелений → squash-мерж самому.
3. Нова версія для телефона = підняти `versionName` (0.X.Y) **і** `versionCode` в `app/build.gradle.kts`.
4. Після мержу в `main` Android сам збирає **підписаний APK** — артефакт `FARIC-Music-Visualizer-vX.Y.Z-Debug` (**живе 3 дні**) і з V177 той самий APK у реліз **`phone-build`** (завжди лише останній; пункт 8 бере звідти — швидко, артефакт — запасний шлях).
   - Артефакт свіжий → faric: `MUSIC VISUALIZER: 3 → 10 → 8` (оновити → статус збірки → завантажити APK).
   - Артефакт протух або мерж був лише документів → `MUSIC VISUALIZER: 3 → 9 → 10 → 8` (9 запускає нову збірку, ~10 хв).
   - Ставити **поверх** старої версії, без очищення даних і без повторного імпорту PNG.
5. Результат («пас / не пас», скрін) — записати в `STATUS.md` (таблиця «Чекає телефона») і `docs/PROJECT_LEDGER.md`, пункт у `TODO.md` → ✔.

## Докази (не плутати)

- Перевірка коду ≠ юніт-тест ≠ зелений CI ≠ **пас на телефоні**. Телефон — джерело правди.
- Три окремі стани: версія в коді · зібраний APK · встановлено на телефоні.
- Не ставити «пас» за faric. Не давати тести для APK, якого ще нема.
- Візуальну синхронізацію з музикою, плавність і пропорції картинок — лише з відео / скрінів з телефона.

## Заборонено / не чіпати

- Просити видалити застосунок, чистити дані, перевстановлювати, повторно імпортувати PNG «для тесту».
- **PNG faric** (герої, рамки, написи, ефекти) лежать у його папках: застосунок їх лише читає за дозволом Android (SAF) — не копіювати в застосунок, не обрізати прозорі краї, не перепаковувати, не стискати.
- `docs/design/PULSEDECK_CENTER_CALIBRATION.md` — координати центрів незмінні.
- Свій ключ підпису; ключі, паролі, токени — не в репо (CI шукає).
- Стандартні сірі вікна й кнопки Android (`AlertDialog`, `android.widget.Button`) — CI-перевірка «Stock app-owned UI guard».
- Нова графіка — якість не гірша за Cyber Shark (`docs/visualizer/ASSET_QUALITY_CONTRACT.md`).
- Інші репо з цього чату не міняти (крім спільного `claude/КОНТЕКСТ.md` проєкту).
- Зсувати номери пунктів меню (нове — наступним вільним номером).

## Постійні правила застосунку

- **Вікна** — лише канонічний шаблон `PulseDeckDialogs.show…` (заголовок · прокрутка · кнопки завжди видно · ≤ 82 % екрана) — `docs/UI_STYLE_CONTRACT.md` → «Канонічне вікно». Нове вікно руками не будувати (CI).
- **Стиль** — `docs/UI_STYLE_CONTRACT.md`: новий елемент успадковує вигляд і поведінку від найближчого наявного (PulseDeck-вікна, кнопки, панелі). Аудит — `docs/UI_STYLE_AUDIT.md`, `docs/audits/2026-10-11-responsive-controls-and-dialogs.md` (текст переноситься, кнопка росте, не обрізається; мін. 48 dp).
- **Одна сесія відтворення** — `docs/assistant-kit/SYSTEM_BEHAVIOR_CONTRACT.md`: поворот / перестворення не запускає пісню вдруге, не створює другий аналізатор чи цикл малювання.
- **Живе відтворення й експорт MP4 малюють однаково** (спільна геометрія й реакції: live Canvas, CPU-експорт, GPU-експорт).
- **Експорт MP4 — є еталон** (`docs/export/EXPORT_ETALON.md`, гілка `archive/export-etalon-v0.19.71`): перед зміною експорту — прочитати; після — той самий замір 3 с / 90 кадрів і рядок у «Журнал замірів». Гірше за еталон — відкотити або пояснити faric.
- **Слово «FARIC» — лише в назвах героїв** (faric 19.10 23:39). У написах, кнопках, заголовках застосунку його нема (застосунок — PulseDeck). Технічні мітки логів (`FARIC-export`) користувач не бачить — можна лишити. `TODO.md` V76.
- **projectM** — сторонній код, ліцензія — `THIRD_PARTY_PROJECTM.md`; оновлення 4.2 — `docs/architecture/PROJECTM_4_2_MIGRATION.md`.

## Технічне

- CI: Java 17, Gradle 9.4.1, `compileSdk 36`, `minSdk 26`, `targetSdk 36`. У середовищі Claude немає Android SDK: Kotlin з `android.*` перевіряє лише CI; чисті класи можна прогнати локально (Kotlin з `/opt/gradle-8.14.3/lib/`).
- Логи Actions через проксі не читаються — причину падіння дивитись в анотаціях: `gh api repos/faric-ua/faric-music-visualizer/check-runs/<id>/annotations`.
- Репо **публічне** — хвилини Actions безкоштовні; але без особистих даних у репо.
- Меню телефона: `MUSIC VISUALIZER` — 1 shell · 2 git status · 3 оновити · 4 показати стан (`STATUS.md`) · 5–7 ключ підпису · 8 завантажити APK · 9 запустити збірку · 10 статус збірки · 11–17 графіка · 18–19 шкурка HUD · 20 документація · 21 прев'ю альбому (V144) · 22 зібрати APK на телефоні (V178: Kotlin — тут, C++ projectM — готовий з релізу `phone-build`; якщо змінено `app/src/main/cpp` — лише GitHub).
