## Source-audited risks and implementation

Prior export flow made two full MP4s simultaneously in app cache (H.264-only plus complete muxed AV), then copied the entire muxed MP4 into MediaStore. Long songs can generate hundreds of MB per copy, fail at the final disk-heavy step, and leave no user-visible file.

- **Android Q+**: directly mux H.264 and AAC from temp inputs into a **seekable pending MediaStore FD**, then set `IS_PENDING=0` only after mux completes; delete partial pending item on failure/cancellation. No duplicate full-length muxed temp/copy. Android 26-28 retains fallback.
- Preflight realistic space estimate using H.264 bitrate, duplicate simultaneous video temp + final target, AAC, optional projectM PCM and safety reserve. Fail early with clear size/free-space explanation rather than spending minutes rendering to a no-space failure.
- AAC transcoder and MP4 copy loops now honor explicit cancellation; video temporary file gets deleted even if video stage fails before AAC/mux; no orphan pending rows.
- Explicit progress phases: **Рендерю відео → Кодую аудіо → Збираю та зберігаю MP4 → MP4 успішно збережено**, with `FARIC-export` stage logs. 100% only after publish.
- Export artist uses actual stored playback metadata (if available); file naming stays `FARIC-Full-*.mp4` in `Movies/FARIC`.
- Separate pure JVM storage budget unit tests. Existing three-second export logic, Player/Scene Host, native renderer, hero/calibration and signing source not modified beyond described export interfaces.
