# FARIC Music Visualizer — документація користувача

**Основний посібник:** [FARIC_USER_GUIDE_UK.md](FARIC_USER_GUIDE_UK.md)  
**Поточна задокументована APK:** **v0.19.43 / build 132** (Android #603 PASS), редакція посібника **1.0 / 2026-10-08**.  
**Мова:** українська.  
**Цільова аудиторія:** користувач застосунку, а не розробник.

## Що описує посібник

Послідовний практичний маршрут: вибрати локальний аудіофайл → керувати відтворенням → вибрати Playback Theme → налаштувати шари та Board → projectM і його FG → зберегти Composition Set → виконати offline analysis → експортувати PNG / пробний MP4 → знайти файл. Окремо: налаштування PulseDeck, типові проблеми, словник і функції «СКОРО».

Оригінальні chat-скриншоти не були записані в GitHub у цьому оновленні; тому GitHub Markdown має інші зображення й відповідні підписи. Не підмінювати це твердженням, що всі скриншоти вже у GitHub.

## Доступ з Termux

У головному меню з'явився **один вкладений пункт `20 — Documentation →`**. Внутрішнє меню відкриває HTML/PDF/DOCX з постійної папки Android, дає доступ до актуального Markdown у GitHub та інших технічних документів. **PDF/DOCX/готовий HTML зі скриншотами не лежать у GitHub як готові файли.** Але `20 → 1` автоматично генерує автономну HTML-довідку з актуального Markdown без ZIP. Для PDF/DOCX та оригінального HTML із тестовими скриншотами один раз завантаж ZIP із чату в `Download`, потім Termux **3 → 20 → 6**. Документи зберігаються в `Documents/FARIC-Music-Visualizer/documentation/v0.19.43/`.

Повні інструкції: [TERMUX_DOCUMENTATION_MENU.md](TERMUX_DOCUMENTATION_MENU.md). Не плутати цей інструмент Termux із меню користувача всередині Android APK. Оновлювати правила підменю разом зі змінами форматів документації.

**Відкладене виправлення:** на скриншоті користувача 2026-10-08 акула на обкладинці PDF має спотворені пропорції. Наступного разу при перевиданні посібника потрібно зберігати співвідношення сторін зображення, рендерити PDF/DOCX та перевіряти сторінку обкладинки вручну. Поточне підменю цього дефекту не виправляє.

## Синхронізація, відновлення та гарантії

**Обов'язковий план:** [DOCUMENTATION_SYNC_CONTRACT.md](DOCUMENTATION_SYNC_CONTRACT.md).

**Стан:** синхронізація всіх Git-tracked документів через Termux **3** працює; збирання й автоматична доставка PDF/DOCX/оформленого HTML **ще не реалізовані**. Окремі файли з чату можуть залишитися тільки на пристрої або у чаті. `20 → 1` може згенерувати HTML з Markdown, коли раніше імпортований HTML відсутній.

У плані: **DOCSYNC-001** (збирання, постійна публікація, контрольні суми і синхронізація всіх форматів однією командою `3`), **DOCSYNC-002** (перевірка актуальності посібника при змінах застосунку). Поки телефонні тести не пройдуть, не позначати як готові.

## Правило підтримки при майбутніх змінах — обов'язкове

Під час зміни вже описаної можливості або додавання нової user-facing функції **у тому ж релізному workflow**:

1. Звірити фактичні кнопки/назви/шляхи з кодом відповідної збірки та телефонними QA (коли потрібні).
2. Оновити `FARIC_USER_GUIDE_UK.md` — розділ, кроки, пояснення, поточну версію та статус функції.
3. Оновити цей README: номер build, короткий запис про нову редакцію й перелік змінених розділів.
4. Оновити або додати ілюстрації, **відрізняючи реальний APK screenshot від макета/референсу**. Не вигадувати зображення як доказ функціональності.
5. Перегенерувати користувацький PDF/DOCX за потреби й перевірити після рендера (немає обрізань/перекриттів, усі табличні рядки читаються, зміст переходить до розділів).
6. Якщо Android CI пройшло, але phone QA ні — зазначати це, не називати функцію прийнятою.
7. Перевірити пріоритетні open issues: `PERF-NAV-002` (підвисання переходів), `BUG-EXPORT-001` (завершення процесу повного експорту на ~48%), `PERF-PLAYER-001` (нерівномірний рух).

**Поточний принцип найменувань:** GF у вихідному коді поки означає комплект героя Shark/Panther; «Аудіоформи» — лише новий майбутній тип, не синонім існуючого GF. Документ `docs/architecture/VISUAL_ELEMENTS_TAXONOMY.md`.
