## 3. Шляхи малювання кадру (хто що рахує — GPU чи CPU)

Вибір іде автоматично за тим, які шари ввімкнені (`ShortVideoExportProof.kt:236–1240`).

| Шлях | Коли | Як | Заміряно (3 с / 90 кадрів) |
|---|---|---|---|
| **А. Повний GPU** (найшвидший) | projectM ✔, GF ✔ з фоном, а FARIC Reactive / Over / Big EQ — вимкнені | projectM малює прямо в текстуру кодера (без копії в пам'ять); світіння, рамка, герой, напис — текстури GPU; на CPU лишаються 3 прозорі шари на весь екран (фон GF, ефекти FX, ефекти + HUD), які щокадру вивантажуються в GPU | **5451 мс** (v0.19.22), 5699–5976 мс (v0.19.38–0.19.44, HUD більший) |
| **Б. projectM через копію** | projectM ✔ + будь-що з FARIC Reactive / Over / Big EQ | projectM рендерить живий `ProjectMView` поза екраном → `glReadPixels` у Bitmap (2 слоти, наступний кадр готується паралельно) → усе малює CPU Canvas → у кодер | ~9915 мс (v0.19.12) |
| **В. Без projectM** | projectM вимкнено | усе малює CPU Canvas; світіння GF — на GPU, якщо ввімкнено | окремо не заміряно |
| **Г. Старі теми** | тема-герой без композиції | `HeroThemeRenderer` / `CyberSharkExportRenderer` на CPU | — |

Порядок шарів у кадрі (шлях А): projectM → світіння → нижній шар (фон GF) → рамка → FX → герой → напис → верхній шар (ефекти + HUD).
Пропорції PNG (v0.19.71): одна функція `BoardBitmapGeometry.fitCanvas` — однаково на екрані, в CPU- і GPU-експорті.
