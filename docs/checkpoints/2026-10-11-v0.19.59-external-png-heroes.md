## How the new feature works

- In Playback Themes or Board, tap **«Зовнішні PNG-герої»**; select `PulseDeck_Heroes` via Android system directory chooser (SAF `OpenDocumentTree`).
- The app requests persisted **read-only** permission to the selected user folder. A background worker indexes its immediate files, accepts only `.png` files with valid actual PNG signature/IHDR, alpha-enabled color type and real transparent pixels; silently non-image file formats cannot be imported as heroes. SHA-256 content identity deduplicates **byte-identical** files, not near-duplicates.
- Choose one hero by readable filename from a scrollable list. The selected PNG becomes the single visible GF Creature object in the existing live HeroBoardView; other GF art parts and synthetic background are hidden. The existing GF model stores reference to an external source, no embedded drawable or new app data image copy.
- Source PNGs stay in the user's Documents folder. No PNG byte copy into app-private storage. Only the actively selected bitmap is decoded in a background task. Gallery scan uses low-resolution thumbnail for transparency validation, then releases it.
- The same source reference is used for offline MP4 export (Canvas/GPU). No large bitmap cache of all ten heroes is created; old eager export decoding of the entire hero catalog was changed to per-current-theme lazy loading. A full RGBA 1254² frame uses roughly 6 MiB of **decoded** RAM while visible, so external files reduce APK size and idle RAM pressure, not displayed artwork RAM to zero.
- Existing four-source GF Mix remains usable. An external PNG can be selected for the Creature slot while frame/fx/wordmark from existing packs remain in the mix. Selected standalone PNG is reversible by choosing a standard Hero; saved scene references remain intact.
- No modifications to immutable `PULSEDECK_CENTER_CALIBRATION`, production Cyber Shark art, music playback, projectM GL ownership, source PNGs, legacy installed hero packs or full-song MP4 mux logic.
